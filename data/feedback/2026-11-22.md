## What did not

1. **The open check has never run.** GitHub starts the scheduled runs hours late. Over 35 trading days (2026-10-05 to 2026-11-20), 0 runs started inside the open window (09:35-12:00 New York). The earliest a run started on any day in the last two weeks was 15:58. The "open" tries are actually doing the close check, and data/alert_state.json has never had an "open" entry. Every row in alert_log.csv is a close-session row.
2. **The close check was missed on 5 of 35 trading days:** 2026-10-12, 2026-11-02, 2026-11-09, 2026-11-16, 2026-11-17. On each of those days the first run started after 17:30 (for example 18:29 on 11-16 and 17:37 on 11-17), so the window had closed and no prices were checked at all. 4 of the 5 are Mondays. It is getting worse: in the last 10 trading days, 2 were missed, and 2 more just made it (17:18 on 11-18, 17:25 on 11-19). 2026-10-12 was VRTX's first day. performance.py says its price touched the buy zone that day, but the first alert came on 2026-10-15.
3. **Sell alerts still stop after valid_until.** The 2026-11-03 review found that scripts/price_alert.py only watches a weekly pick until its valid_until date, so NVDA's stop (2026-10-23) and VRTX's target (2026-10-30) were never alerted. The code has not changed. This matters again as soon as a new pick is made.
4. **Very few rule-based picks.** 4 weekly runs (2026-10-05, 10-12, 11-02, 11-09) gave 8 sector slots. They produced 1 rule-based pick (VRTX) and 1 approved exception (NVDA). The last 2 runs gave no picks at all. The 2026-11-03 review set a trigger: if the rate stays near 1 in 6 for 3 or more weeks, look at how scripts/indicators.py sets targets. That trigger has now been met. Part of the cause may be the market. The new data/sector_scan.json (created 2026-11-22 13:52) shows QQQ at 608.45, down 13.63% in 1 month and 13.77% in 3 months, below its 200-day average, with VIX at 35.89. In a falling market, few stocks pass an uptrend and 2.0 reward to risk test, and having no picks may be the right result.
5. **Watchlist alerts can send "SELL" for stocks that were never in the buy zone.** AVGO's target alert and NVDA's stop alert both fired with no buy-zone alert first. This is fine if Top already held the stock. If he did not, the alerts are noise. evaluate_pick does not check whether the buy zone was reached first.

## Proposed changes

Only 1 change. It is a process fix, which is allowed while enough_data is false. No score weights or pick rules are proposed.

**Change 1: widen the close alert window into the evening**

- Setting: `alerts.close_window_et` in config/strategy.json
- Current value: `["15:00", "17:30"]`
- New value: `["15:00", "23:59"]`
- Evidence: Over 35 trading days, the close check ran on 30 and was missed on 5 (2026-10-12, 11-02, 11-09, 11-16, 11-17) because every run that day started after 17:30. The counting script shows that with a 15:00-23:59 window, all 35 of 35 days would have had a close check. GitHub's own delays caused these misses, not market rules. Each day already has 6 tries, and the later ones (which now start around 20:00 to 23:00 New York and skip right away) would become real backups. price_alert.py asks for regular-hours prices only (`prepost=False`), so a run in the evening reads that day's 4:00 PM close. scripts/alert_gate.py still makes the extra tries skip once one has finished, so there are no double alerts. Alerts already arrive after the close (16:56 to 17:25 last week), so acting on them the next morning is no change.
- What would show it was a mistake: (a) an evening alert in alert_log.csv whose price does not match that day's official close (after-hours prices leaking in), (b) the same event sent twice on one day, (c) an evening run that saves the wrong date in alert_state.json, or (d) a close check still missed on any trading day in the next 2 weeks.
- Note: this only fixes the close check. The open check cannot be fixed with a setting, since no run has started before 14:20 New York in the period checked. See below.

No second change. The low pick rate is real, but the only lever in strategy.json would be lowering `technical.min_reward_risk` (2.0). The one pick below 2.0 lost, the one at 2.0 or above won, and the market is falling. There is no evidence for lowering it.

Outside strategy.json (for Top to decide, these are code changes, not settings):
- Fix scripts/price_alert.py so an entered pick stays watched for target and stop until it exits or `performance.max_holding_trading_days` (20) runs out. This is still open from 2026-11-03, and it is the biggest risk once picks come back. Add a test in tests/.
- Decide what to do with the open check. Options: accept one check a day and remove the open tries, or trigger the workflow from an outside scheduler that runs on time.
- Optional: only send target and stop alerts for watchlist stocks after the buy zone was reached, or say in the message that the zone was never reached.
- With the pick-rate trigger now met, review the target rule in scripts/indicators.py with Top (not the 2.0 floor). This would need a test and approval.
