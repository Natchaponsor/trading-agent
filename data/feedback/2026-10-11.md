## Data quality warnings

1. **change_log is out of step with the version history.** config/strategy.json says version 2, last_changed 2026-10-05, but change_log has only one entry, dated 2026-10-04 and labeled version 2, "Starting settings". Git shows a separate commit, "Widen alert windows (strategy v2)". The v1 to v2 change on 2026-10-05 (alert windows widened) has no change_log line. The starting entry should probably say version 1. Suggest the main session fix the log after Top approves. I did not edit the file.
2. **Version mismatch across the week.** The NVDA pick is tagged strategy_version 1, but alerts ran under v2 settings from 2026-10-05. This is harmless here (v2 only widened alert windows, and the entry alert was in the close window) but it should be noted for later version-split analysis.
3. **Open pick shows an exit_day.** performance.json lists exit_day 2026-10-09 for an open pick. This is the last priced day (mark to market), not a real exit. Do not read it as a closed trade.
4. **Pick validity vs tracking.** The pick's valid_until was 2026-10-09, but the tracker holds entered picks up to `performance.max_holding_trading_days` = 20. That is expected behavior, not an error.
5. **my_trades.csv is empty.** There is no record of whether Top actually bought NVDA, so real results can't be compared with the picks. If a trade was made, please log it, including the smaller position size.
6. **Exception picks are mixed into the totals.** performance.py has no separate handling for picks with an "exception" field. When more picks close, exception picks should be reported apart from rule-based picks so they don't skew the scoreboard.
